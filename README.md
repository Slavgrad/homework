# Python для устойчивых моделей – занятия и домашние задания

Репозиторий курса: конспекты занятий (Jupyter-ноутбуки) и домашние
задания с автоматической проверкой через GitHub Actions.

## Материалы занятий

- [`python_лекция_занятие_1.ipynb`](python_лекция_занятие_1.ipynb) —
  занятие 1: как исполняется программа, архитектура ЭВМ, память и
  ссылки на объекты, `==` против `is`, изменяемые и неизменяемые
  объекты, числовые типы.
- [`python_лекция_занятие_2.ipynb`](python_лекция_занятие_2.ipynb) —
  занятие 2: строки и форматирование, коллекции (список, кортеж,
  словарь, множество), файлы и сериализация, ветвления, циклы,
  протокол итерации.

Открывайте их в Jupyter/JupyterLab или VS Code — это тот же материал,
который разбирался на занятии, с примерами кода.

## Домашние задания

Каждое домашнее задание закрывает материал одного занятия и лежит в
своей папке в [`homeworks/`](homeworks/) со своим `README.md`:

- [`homeworks/hw01_lecture1/`](homeworks/hw01_lecture1/) – домашнее
  задание 1, по материалу занятия 1 (10 задач).
- [`homeworks/hw02_lecture2/`](homeworks/hw02_lecture2/) – домашнее
  задание 2, по материалу занятия 2 (10 задач).

Решение пишется **в существующем файле** внутри папки задания
(например, `homeworks/hw01_lecture1/hw01.py`) – вы дополняете
функции, которые сейчас заканчиваются на `raise NotImplementedError`,
своим кодом. Ничего больше в файле менять не нужно.

## Быстрый старт

1. Установите Python 3.10+.

2. Получите **свою собственную копию** этого репозитория: откройте
   ссылку, которую даст преподаватель, и нажмите зелёную кнопку
   **Use this template → Create a new repository** – GitHub создаст
   отдельный репозиторий в вашем аккаунте со всеми файлами и уже
   настроенной автопроверкой. Затем склонируйте **свою** копию к себе
   на компьютер:

   ```bash
   git clone <ссылка-на-ваш-репозиторий>
   ```

   **Важно**:️ Работайте именно в своей копии, а не в оригинальном
   репозитории – иначе push не пройдёт (у вас не будет прав записи) и
   вашу автопроверку никто не увидит.

3. Установите зависимости для проверки:

   ```bash
   pip install -r requirements.txt
   ```

4. Откройте нужное задание, например `homeworks/hw01_lecture1/hw01.py`
   (или `homeworks/hw02_lecture2/hw02.py`), и реализуйте функции по
   описанию в docstring и в README.md той же папки.

5. Проверьте решение локально **до** отправки:

   ```bash
   pytest tests/hw01 -v   # для задания 1
   pytest tests/hw02 -v   # для задания 2
   ```

   Все тесты должны быть зелёными (`PASSED`).

6. Закоммитьте и запушьте решение в свой репозиторий:

   ```bash
   git add homeworks/hw01_lecture1/hw01.py homeworks/hw02_lecture2/hw02.py
   git commit -m "Решение домашних заданий 1 и 2"
   git push
   ```

   Через 1–2 минуты откройте вкладку **Actions** в своём репозитории
   на GitHub и покажите преподавателю ссылку на неё (или прямо на
   зелёную/красную галочку у своего коммита) – это и есть результат
   проверки.

## Что происходит после отправки

При каждом `push` и `pull request` автоматически запускается GitHub
Actions (файл [`.github/workflows/homework-check.yml`](.github/workflows/homework-check.yml)),
который:

1. устанавливает Python и зависимости;
2. запускает `pytest` по всем тестам домашних заданий;
3. публикует результат – во вкладке **Actions** репозитория, в
   разделе **Summary** запуска, появится таблица: какой тест прошёл
   (✅), какой не прошёл (❌) и почему.

Если хотя бы один тест не прошёл – весь запуск (job) помечается как
неуспешный (красный крестик рядом с коммитом/PR), но это не сломает
и не изменит ваш код: это просто отчёт о том, что нужно доработать.

## Если тесты падают с `ModuleNotFoundError` или ошибкой импорта

Запускайте `pytest` из **корня репозитория**, а не из папки задания –
структура импортов настроена относительно корня (см. `pyproject.toml`).

## Если что-то не понятно

Сначала посмотрите docstring нужной функции и README папки задания –
там есть примеры и уточнения формата. Если вопрос остаётся –
спрашивайте у преподавателя.
